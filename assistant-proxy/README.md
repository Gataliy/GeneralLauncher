# Прокси для ассистента (Groq)

Облачная функция (Cloudflare Worker) между лаунчером и Groq API. Ключ Groq хранится только в секретах сервиса и не попадает ни в репозиторий, ни на магнитолу. Модели те же, что в дашборде (Tomsk Hub).

## Развёртывание

1. Установите Wrangler: `npm install -g wrangler`, затем `wrangler login`.
2. Из этой папки выполните:
   - `wrangler secret put GROQ_API_KEY` и вставьте ключ (ключ `gsk_…` в чат присылать не нужно);
   - по желанию `wrangler secret put APP_TOKEN` (придуманная строка для доступа с магнитолы; без неё адрес открыт тому, кто его знает);
   - `wrangler deploy`.
3. Адрес вида `https://<имя>.<аккаунт>.workers.dev/chat` задайте в лаунчере (`DEFAULT_PROXY_URL` в `exit/assistant.js`; его же можно ввести в окне ассистента, раздел «Подключение»). Токен `APP_TOKEN` вводится на магнитоле один раз в окне ассистента.

Имя сервиса в `wrangler.toml` (`gemini-proxy`) не менял: новое имя дало бы другой адрес, и уже работающий `jct-proxy` перестал бы отвечать. Переименовывать только вместе с обновлением адреса в лаунчере.

## Модели

- основная: `openai/gpt-oss-120b` (переменная `GROQ_MODEL`);
- запасная: `llama-3.3-70b-versatile` (переменная `GROQ_FALLBACK_MODEL`), используется, если основная отвечает ошибкой или пустым ответом.

## Что разрешено

Модель может предложить одно действие из трёх видов:

- `climate_command` — команда климата из `ALLOWED_COMMANDS` в `worker.js`;
- `calendar_event` — событие в Google-календаре (название, время с часовым поясом, место);
- `task_add` — задача в Google Tasks.

Окна, люк, багажник, двери и замки в ассистент не входят. Лаунчер проверяет действие ещё раз и выполняет его только после подтверждения на экране.

## Проверка

`node assistant-proxy/test/worker.test.mjs` запускает прокси с подменённым вызовом Groq и проверяет разрешённые и запрещённые действия, токен, запасную модель, историю и разбор ответа.
