# Прокси для ассистента Gemini

Облачная функция (Cloudflare Worker) между лаунчером и Gemini API. Ключ Gemini хранится только в секретах сервиса и не попадает ни в репозиторий, ни на магнитолу.

## Развёртывание

1. Установите Wrangler: `npm install -g wrangler`, затем `wrangler login`.
2. Из этой папки выполните:
   - `wrangler secret put GEMINI_API_KEY` и вставьте ключ (в чат его присылать не нужно);
   - по желанию `wrangler secret put APP_TOKEN` (придуманная строка для доступа с магнитолы; без неё адрес открыт тому, кто его знает);
   - `wrangler deploy`.
3. Адрес вида `https://<имя>.<аккаунт>.workers.dev/chat` задайте в лаунчере (`ASSISTANT_PROXY_URL` в `exit/assistant.js`). Токен `APP_TOKEN` вводится на магнитоле один раз в окне ассистента.

## Модель

По умолчанию `gemini-3.8-flash`. Если такой модели нет, задайте другую переменной `GEMINI_MODEL` (`wrangler vars` или в настройках сервиса) и проверьте список моделей через Gemini API `models.list`.

## Что разрешено

Модель может предложить только `climate_command` с одной из команд из `ALLOWED_COMMANDS` в `worker.js`. Окна, люк, багажник, двери и замки в ассистент не входят. Лаунчер проверяет действие ещё раз и выполняет его только после подтверждения на экране.

## Проверка

`node assistant-proxy/test/worker.test.mjs` запускает прокси с подменённым вызовом Gemini и проверяет разрешённые и запрещённые действия, токен и разбор ответа.
